#### 你必须会答的题
**题目：如果给 Cgroup 做一个 Web 资源管理界面，你怎么设计？**

#### 标准答案框架
> 我会先拆成两类接口：
> 1. 配置类操作，比如创建/更新资源限制，走普通 REST API；
> 2. 监控类数据，比如 CPU/内存/IO 使用情况，如果只是秒级刷新，可以先用轮询；如果需要更高实时性，再考虑 WebSocket 或 SSE。  
> 后端会做一层采集和缓存，避免每次都直接打到底层；前端会做刷新频率控制、异常提示和权限隔离；如果有管理操作，还要补审计日志和回滚能力。

### 4. Rust / OS / 并发基础题标准化

#### 目标
把“懂但说不标准”变成“说得稳”。

#### 必练题目
- Rust 相比 C++ 的优缺点
- Rust 如何保证内存安全
- Rust vs Go vs Java / Python
- 进程、线程、协程区别
- 用户线程与内核线程区别
- 什么场景适合协程

#### 输出要求
每题练成：
- 30 秒版
- 1 分钟版

#### 示例：Rust 如何保证内存安全
> Rust 主要通过编译期机制保证内存安全，而不是依赖运行时兜底。核心包括所有权、借用检查和生命周期约束，它们能减少悬垂指针、重复释放和非法引用等问题。在并发场景下，Rust 还通过类型系统限制 data race。只有显式使用 unsafe 才能绕开这些规则，所以风险边界是清晰可见的。

### 7. 模型能力和 AI 工程化认知

#### 目标
把你原本已经有优势的点说得更成熟。

#### 建议表达
不要只说“某模型更强”，要按场景说：
- 深度编码：更强推理和长上下文能力
- 快速生成：低成本模型即可
- 调试修复：需要更稳定的 reasoning
- 大项目：更重视上下文治理和 workflow，而不只是模型本身

#### 推荐结论
> 我觉得模型上限当然重要，但真正决定 AI Coding 可用性的，往往是任务边界、测试约束、上下文治理和流程工程化，而不是只换一个更强模型。

#### 目标

4. 如果我后续想往工程平台或 AI 应用工程方向深挖，这个岗位里会有对应机会吗？

#### 不建议再问得太泛
比如：
- 你们做什么业务线
- 我能干啥

可以问，但最好更聚焦。
