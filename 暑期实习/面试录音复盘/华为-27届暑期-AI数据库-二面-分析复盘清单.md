## 逐题复盘

### 1. 操作系统 / 内核学习方式

**问题**：大学期间最感兴趣的是哪门课？操作系统这一块看过哪些书？你是怎么入门内核开发的？

**我的回答原文**：
- 最感兴趣的是操作系统和计算机组成原理，觉得偏底层的东西比较“耐嚼”；
- 正式的教材没系统看完，更多是直接跟着项目做，参考 Linux 源码和文档来“摁造”；
- 写 cgroup 时，一开始看了 Linux cgroup v1 文档发现太复杂、且已废弃，于是转看 v2 文档，再结合源码和网上深度调研文章；
- 使用 Claude Code 作为“老师”，带着自己读源码、搭框架，从而做出自己版本的 cgroup 实现。

**不足**：
- 表达中“没怎么看书”“摁造”这类说法容易让人感觉学习路径偏随意，虽然实际投入很多，但对面试官的第一印象会有一点打折；
- 没有主动提到自己计划系统补齐哪些经典教材或课程（如《操作系统概念》《OSTEP》等），缺少“工程实践 + 理论补齐”的闭环表述。

**回答关键词**：操作系统、计算机组成原理、Linux 源码、cgroup v2 文档、AI 辅助读源码、自主搭建框架

**参考回答**：
> 在学校的专业课里，我最感兴趣的是操作系统和计算机组成原理。一方面是课程本身，另一方面是可以直接和我在做的自研内核项目打通。
>
> 入门内核开发的时候，我的路径大概是三步：
> 1. **先有一个整体概念**：通过课程和一些经典资料（比如 CS:APP、操作系统课程），先知道进程、内存管理、系统调用这些大模块大致在做什么。
> 2. **再结合具体模块深入**：比如要做 cgroup，我会先看 Linux 官方文档，搞清楚 v1 和 v2 的差异、控制器的能力、树形结构等，再配合源码和社区文章理解实现细节。
> 3. **最后边做边补**：真正落地实现的时候，我会把自己项目里的结构和 Linux 进行对照，用 AI 帮忙梳理调用链、找关键数据结构，然后再回过头去补相关书籍和论文，形成自己的知识体系。
>
> 后面如果有机会做 AI infra，我也会沿用这套“先框架后细节、项目驱动再系统补齐”的方式来学习底层系统和算法。

### 2. 团队分歧与 Nix 配置争论

**问题**：在实验室项目中，有没有和其他成员产生意见分歧的情况？你是怎么处理的？

**我的回答原文**：
- 例子是关于是否有必要维护一套 Nix 环境配置；
- 组长认为直接给大家配置统一开发机就够了，觉得 Nix 维护成本高、价值不明显；
- 自己认为 Nix 可以极大减少环境差异，举了 Ubuntu 20.04/22.04 下脚本拉工具链不一致的例子；
- 最后拉了三四个人开飞书会议，对齐信息、讨论利弊，组长了解更多细节后接受并支持维护 Nix 配置。

**不足**：
- 故事本身非常好，但可以再强调一下“我如何兼顾技术正确性和团队资源”的平衡，比如在推动 Nix 的同时，也关注维护成本、文档完善、对新同学的学习曲线等；
- 可以顺带补一句“如果最后结论是放弃 Nix，我也能接受，只要大家是基于同一组信息做决策”。

**回答关键词**：Nix 配置、开发环境统一、信息差、飞书会议、对齐认知、共识决策

**参考回答**：
> 在实验室里比较典型的一次分歧是：要不要长期维护一套 Nix 配置。
>
> 组长一开始更倾向于直接给大家配置一台统一的开发机，觉得 Nix 的维护会增加复杂度；而我这边因为踩过 Ubuntu 版本不一致导致脚本拉工具链失败的问题，所以比较坚持“用 Nix 固化环境”的做法。
>
> 我当时的处理方式是：
> 1. 先把自己遇到的环境问题整理成几个具体例子，列清楚成本和收益；
> 2. 拉上组长和另外几位同学开了个短会，把这些信息和我预期能解决的问题讲清楚；
> 3. 听完大家的顾虑，比如维护成本、新人学习成本，然后一起权衡；
> 4. 最后大家达成共识——在保证配置尽量简单的前提下，保留 Nix 方案，并补充文档，减少后续维护成本。
>
> 对我来说，更重要的是信息对齐和共识，而不是一定“赢”某个技术选型，只要结论是团队基于完整信息做出的，我都能接受并执行。

### 3. 主导任务与分工（Serverless 扩缩容 / 认证模块）

**问题**：在项目中有没有你主导、其他人参与的事情？你是怎么制定目标、计划和分工的？

**我的回答原文**：
- 讲了在 serverless 容器平台项目中，自己负责调研扩缩容模块，带一位学弟一起做；
- 先在飞书上建共享文档，把扩缩容逻辑拆成几个模块，按难度和依赖关系分给学弟和自己；
- 约定周二出阶段性报告，自己 review 后准备周四周会的整体汇报；
- 在过程中发现根据整体架构，这个扩缩容模块在当前版本其实没必要实现，于是及时终止，随后转而带学弟做认证模块（设计数据库表、封装数据库层等），自己负责 code review 和 PR 审查。

**不足**：
- 很好的 leadership 案例，但如果能再补充“哪些指标或信号让你判断该模块可以砍掉”，会更体现你对业务价值和简化系统的关注；
- 可以略提一下“学弟在过程中遇到的问题”和“你是如何辅导他解决”的细节，让“带人”这个点更立体。

**回答关键词**：serverless、扩缩容、任务拆分、飞书共享文档、按难度分工、及时止损、带学弟、代码评审

**参考回答**：
> 在 serverless 平台项目里，有一段时间我是主导一个扩缩容子模块的调研和设计。
>
> 当时组长把这个方向交给我，我拉了一位学弟一起做。我的做法是：
> 1. 先在飞书上建一个共享文档，把扩缩容流程按“监控指标 → 策略决策 → 实例拉起/回收”拆成几个模块；
> 2. 根据难度和依赖关系，把相对独立、上手门槛低的部分分给学弟，比如监控指标和配置读取，我自己负责整体策略和与容器管理的集成；
> 3. 约定好节奏，比如周二前出阶段性调研报告，周四周会上做汇报。
>
> 在准备整体汇报时，我们和组长一起审视了这个模块对当前版本的价值，发现按照“轻量化、尽快可用”的目标，这一版其实可以先不做扩缩容，只保留最小可用集。于是我就带着学弟及时止损，转而做认证和数据库这一块，把已经学到的东西沉淀下来。
>
> 后面在做认证模块时，我主要负责给出数据表设计、接口规范和代码评审，让学弟在可控范围内独立实现，并在 PR 里给他具体的反馈。这样既保证了整体质量，也让他有比较完整的成长路径。

### 4. 挫折与压力应对（ACM 选拔）

**问题**：在大学或项目经历里，有没有让你觉得比较挫折或失败的事情？你是怎么走出来、调整自己的？

**我的回答原文**：
- 讲了大一参加 ACM 校队选拔的经历：自己基础最弱，提前刷了很多题，但第一场选拔因为紧张、解题思路选择不当（用 DFS 而不是更简单的遍历），导致卡在一道简单题上，最终没进前十；
- 出考场后情绪很低落，觉得“大学第一场选拔就失败”，一度怀疑自己；
- 在队友安慰和鼓励下，重新把题目复盘、补基础、继续刷题，为后两场做准备；
- 最终在后续选拔中正常发挥，成功进队。

**不足**：
- 故事本身很真实，也展示了恢复能力，但可以再多讲一点“从这次挫折中具体学到了什么”，比如：复盘的重要性、不要在压力下贸然换思路等；
- 可以补一句“后来在其他场景里如何应用这个经验”，让故事从单点经历变成方法论。

**回答关键词**：ACM 选拔、算法题、复盘、继续刷题、队友支持、抗压能力

**参考回答**：
> 大一的时候，第一次参加 ACM 校队选拔对我打击挺大。当时前期准备得很认真，但正式比赛时因为紧张和思路走偏，卡在一道本该不难的题上，最后没进前十。
>
> 出考场那一刻确实挺难受的，会本能地怀疑自己是不是不适合搞算法。但冷静下来之后，我做了几件事：
> 1. 把那场比赛所有题目重新做了一遍，尤其是卡住那道题，认真分析自己当时为什么会选错思路；
> 2. 和队友一起复盘，全程复现我在比赛中的决策过程，从中找出可以调整的习惯，比如不要在压力下频繁换解法、要先把朴素方案实现出来；
> 3. 给自己定了一个比较实际的目标——不追求“必须进前几名”，先把后两场发挥稳定，保证训练成果能体现出来。
>
> 这件事对我后面帮助挺大：无论是做项目还是准备面试，我都习惯把“失败的那一次”当成学习样本，复盘原因、调整方法，而不是简单地把它看成一场输赢。

### 5. 家庭冲突与情绪管理

**问题**：有没有别人触碰你底线、让你比较愤怒或委屈的事情？你是怎么处理和反思的？

**我的回答原文**：
- 举了和父亲因为过期牛奶争执的例子：出于关心把过期几天的牛奶直接丢掉，父亲觉得不被尊重、很生气；
- 当时自己态度也比较强硬，坚持认为“有问题就应该丢”，两人情绪都上来了；
- 冷静一段时间后，在母亲的劝解下意识到问题更多在于态度和尊重，而不只是“牛奶该不该丢”；
- 之后写了几百字的文字向父亲道歉、买衣服表达心意，父亲也坦诚自己当时心情，最后关系恢复。

**不足**：
- 故事非常真诚，但面试场景下可以稍微压缩细节，重点放在“情绪调节”和“主动沟通”上；
- 可以再明确总结一两条原则，例如“先稳定情绪再讲道理”、“反思自己的表达方式”等，让面试官更容易抓到你的处理模型。

**回答关键词**：家庭冲突、尊重、态度、主动道歉、写信沟通、情绪管理

**参考回答**：
> 比较触碰到底线的一次，是回家时和父亲因为一盒过期牛奶产生的冲突。出发点其实都是关心，但当时我在表达上比较强硬，没有给他足够的尊重，他也觉得自己被否定了，两边情绪一下子都上来了。
>
> 这件事对我最大的启发有两点：
> 1. **情绪永远比道理优先**：人在情绪很激动的时候，其实听不进去太多“谁对谁错”的分析，这时候先降温、再谈问题比当场争个输赢更重要；
> 2. **要敢于承认自己的表达问题**：冷静下来后，我意识到自己在语气和态度上的问题，就主动写了一封长一点的道歉信，把当时的想法和反思讲清楚，再当面沟通。后来父亲也坦诚了自己的感受，事情就过去了。
>
> 现在无论在团队合作还是生活里，遇到类似冲突时，我会先问自己“对方现在是理性状态还是情绪状态”，如果是后者，会优先做情绪缓和和信息对齐，再谈具体方案。

### 6. 职业规划与 AI infra 岗位理解

**问题**：这次尝试的是 AI 算法相关岗位，你对这个岗位的理解是什么？后续的职业规划怎么想？

**我的回答原文**：
- 认为 AI infra / AI 算法方向是未来大势所趋，希望能进入这个方向学习底层大模型、调优等；
- 在学校主要是做内核和容器，AI 课程比较少，希望通过进入岗位获得系统的学习路径和资源；
- 表示自己已经大量使用 Claude Code 等工具辅助开发，相信 AI 会“侵入式地接管”很多软件工程工作；
- 备选方向是偏底层的后台开发岗位，但优先希望留在 AI 相关团队。

**不足**：
- 对岗位本身的理解偏宏观（“未来趋势”“大势所趋”），可以再结合具体团队的方向（如向量数据库、AI agent）讲讲自己能立刻贡献的点；
- 没有明确列出“目前已经具备的能力”与“需要补齐的能力”，让面试官快速看到你在这个岗位上的短期价值和长期成长空间。

**回答关键词**：AI infra、AI 算法、向量数据库、底层系统、长期发展、补齐理论

**参考回答**：
> 我对 AI infra/算法岗位的理解，一方面是“未来方向”，另一方面也是“和我现在的积累比较吻合的地方”。
>
> 从现在的经历看，我在自研内核、容器、资源管理这块有比较扎实的底层实践，也大量使用过 Claude Code 这一类工具辅助开发，对“AI 如何嵌入工程流程”有直接体验。我希望在 AI infra 团队里，把这种底层和工程经验迁移到：
> - 做向量数据库或相关基础组件的性能优化和资源管理；
> - 把 AI 辅助开发的工作流应用到我们自己的系统中，比如自动分析 crash、生成排查报告等。
>
> 同时我也很清楚自己的短板：在模型训练、推理优化、算子等方面的理论基础还不够系统。所以我会把前期的目标放在“用现有的系统能力尽快对团队产生价值”，比如先承担一些工程向的任务（向量索引构建、存储引擎相关工作），在这个过程中系统补齐必要的数学和算法基础，再逐步往更偏算法的方向走。

## 必背答案清单

1. **如何自学和实现一个内核模块（如 cgroup）**：从官方文档和源码入手 → 用 AI 带着读代码 → 搭出自己的数据结构和调用链 → 通过测试和对照验证正确性。
2. **如何处理技术分歧（如 Nix 配置）**：先把问题具体化、列举例子 → 对齐信息差 → 共同权衡成本收益 → 不执着于“我赢了”，而是“团队基于完整信息做决策”。
3. **如何讲述自己主导的一个任务**：背景 → 目标 → 拆分 → 分工 → 节奏控制 → 结果（包括及时止损）→ 自己在其中的角色和成长。
4. **描述一次挫折与恢复历程（ACM 选拔）**：发生了什么 → 当时的情绪和困难 → 做了哪些具体行动（复盘、练习、调整心态）→ 最后得到什么 → 这套方法后来如何再次使用。
5. **为什么选择 AI infra / AI 算法方向**：结合自己当前的底层和工程经验，说明能立刻贡献的点，以及未来要补齐的理论部分，避免只停留在“趋势很火”的层面。

## 复盘

### P0

**行为面问题结构化表达**
- 关键词：STAR（情境-任务-行动-结果）、案例选择、收获总结
- 练习方向：选 4–5 个高质量案例（团队分歧、主导任务、挫折应对、家庭冲突、社团收获），按 STAR 结构写成短文，保证每个答案都能在 2–3 分钟说清楚，并能明确点出“我学到了什么”。

**职业规划与岗位匹配度**
- 关键词：岗位需求、现有能力、短期贡献、长期发展
- 练习方向：针对“AI infra / 向量数据库 / AI 算法”整理一份岗位理解，将“我能马上做什么”“我需要系统补什么”分成两栏，面试时重点围绕这两栏回答，而不是泛泛谈趋势。

### P1

**内核 / 容器项目的讲解方式**
- 关键词：项目背景、规模感、自己的贡献、与岗位的关联
- 练习方向：把 DragonOS / cgroup / loop / serverless 各写一段 1 分钟的介绍稿，每段都包含：这是个什么项目 → 我具体做了什么 → 用到了哪些关键技术 → 这些和 AI infra/数据库有什么关联。

**情绪和冲突管理的总结**
- 关键词：情绪优先、主动沟通、承认错误、尊重
- 练习方向：把家庭冲突案例再压缩到 1 分钟以内，突出“我如何从中形成了一套处理冲突的原则”，少讲细节，多讲方法论。

### P2

**AI 理论与基础知识补齐**
- 关键词：向量表示、相似度度量、索引结构、训练/推理基础
- 练习方向：花时间补读向量数据库、检索和基础模型知识，至少能流畅地讲清楚向量检索的基本流程和常见索引结构（如 HNSW、IVF 等），为后续技术面打基础。

这场二面整体偏综合素质和匹配度考察，没有再进技术细节，但从对话中可以看出：你在底层项目实践、团队协作、情绪管理和表达能力方面有比较全面的优势。对于 AI infra / AI 算法岗位，面试官更关心的是“你是否适合长期做技术”和“你是否能在团队环境下稳定成长”，而这一点你已经通过很多例子给出了正面信号。
