# 操作系统八股

### 进程 线程 协程 
1. 进程 ： 运行中的程序叫作进程 ，上下文切换开销大，有独立虚拟内存空间 ，页表文件描述符，内核堆栈，变量，链表方式组织，是资源分配的单位

2. 线程：共享相同地址环境 ，进程中的一条执行流程 ，线程是cpu调度的单位 ，同进程之间的线程数据传递不用经过内核，抢占式调度，TLB 会刷新

   TLB 是什么？ 页表缓存 

3. 协程 ： 是由用户态实现的，用于 高io下的虚拟化线程，能自行保存所有的变量函数堆栈在堆中，协作式调度 ，无法利用多核

协程和进程区别 ： 切换代价 ，栈管理（协程是用户栈可动态扩展），阻塞影响：线程可执行其他协程，线程可以多核但是协程只在一个线程上运行，只能绑定一个核心，所以 线程适合高密度计算，但是协程适合高io

在内存中 进程和线程的表现都是 task_struct ，通过 clone()标志位实现

### 多路复用 

- Select ： 每次会把所有监视的fd拷贝到内核态，线性遍历所有fd，有更新再标记拷贝到用户态，位图，受限于FD_SETSIZE常量，只能监听1024个fd

- poll： 拷贝，数组，将请求时间和返回事件分开

- epoll： 通过事件驱动 ,红黑树 ，回调机制和就绪链表 ，解决拷贝开销，解决遍历开销，解决规模限制
  - 水平触发： 有数据就一直提醒，性能较低
  - 边缘触发： 数据增加才提醒，非阻塞io

# 计网八股 

讲讲 Tcp 和 udp 

tcp 和 udp 都是传输层的协议 ，tcp 是面向连接 的 ，所以每次连接前会有三次握手，udp 是无连接的，没有握手 

tcp 通过确认应答，流量控制，拥塞控制来保证其可靠性，但是 udp 是不可靠的

tcp 是面向字节流，所以 tcp 可能会出现粘包问题，但是 udp 是面向报文的，不会出现粘包问题

故引入 quic ： 在应用层自己实现可靠性 ，udp+自定义加密握手+可靠机制+多路复用

tcp 太保守 ，会产生对头阻塞，连接建立延迟高，尤其是三次握手+tls
第一次握手失败： 重传五次，第五次没有回应会直接断开



http 基于文本分割 ，但是 http2 改用帧格式

http请求：

解析域名，找到 host  

找 dns ，先找缓存，挨个从根 dns 请求得到我们要的 ip 地址，然后根据 ip 地址和其对应的端口，打包tcp，分装好 ip 头，找 ip 对应的 mac 地址，在局域网内通过 每一条都重新封装 mac 地址

tcp 三次握手 syn ack+syn ack 优化 ： 第一次握手带数据 1-RTT， quic ：0-rtt 或 1-rtt

tls 握手 client hello serverhello  。。。 tls 1.3 在一开始就发了多个随机数 
滑动窗口： 流水线批量发送，提高传送效率，累计应答
流量控制： 控制发送方到接收方 ，防止接收方缓存不够，被发爆了
拥塞控制：发送发-》整个网络链路，怕的是堵死丢包延迟变大



tcp的close_wait ：在被动关闭方，收到fin并恢复 ack 后进入该状态，内核告诉应用程序快点调用close()

tcp的time_wait: 保持2msl，目的是防止最后ack丢失 ，注意： 所有的纯ack行为是不会自己重发的，还要防止迷路报文即旧的报文进入新连接

# 分布式



CAP理论

1. Consistency：所有服务器访问数据一样
2. Availability：非故障节点请求合理时间内得到响应
3. Partition Tolerance：信息孤岛也能继续运行

衍生出BASE理论：

- Basically Available：基本可用
- Soft state：允许存在中间状态
- Eventually consistent：最终所有节点上的数据是一致的 

1. 2pc （Two-Phrase-Commit）

   1. 容易死锁，伪装成一个单机数据库 ，保证绝对的一致

2. 3pc （CanCommit-PreCommit-DoCommit)

   1. 可能会产生脑裂，因为在Precommit有个超时自动提交机制，如国协调者回滚，将有两份数据

      

3. TCC（Try-confirm-cancel）

   1. 资源预留，端事务，高侵入
   2. 需要为每个业务写三个接口，还要防悬挂，防幂，防空回滚

4. 可靠消息最终一致性（MQ方案）

   1. 基于base，发起方写完本地数据库，发消息给消息队列，由其投递下游
   2. 本地消息表
   3. 最大努力通知
   4. 不回滚

5. Saga模式 

   1. 极致吞吐和灵活性
   2. 长事务，流程多 ，按顺序补偿
   3. 几乎无资源锁定 ，隔离性缺失，可以通过 语义锁，id标示等保证防止超卖
