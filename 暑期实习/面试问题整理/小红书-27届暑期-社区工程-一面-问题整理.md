小红书-27届暑期-社区工程-一面-问题整理


面试问题

一、个人与项目背景

1. 简单自我介绍，以及最近主要做过的项目和与 AI 使用相关的经历。
2. 为什么会去做开源社区里的内核开发？这是兴趣还是机遇？
3. 你是想学 Rust 吗？是什么吸引你选择 Rust 这门语言？

二、语言与系统基础（Rust / C++ / 服务端）

4. 你觉得 Rust 在语言设计上相对于 C++ 有哪些优劣势和特性？
5. Rust 是如何通过生命周期和所有权来保证内存安全的？
6. 相比于 Go、Python 这类服务端语言，Rust 在系统编程方面有哪些不同和优势？为什么说 Go/Python 不太适合写底层系统？
7. 在操作系统中，进程、线程和协程之间的区别是什么？
8. 内核线程和用户线程在调度开销和阻塞处理上有什么不同？

三、AI 辅助开发与工程实践

9. 在开发过程中，你是怎么使用 AI 工具的？这些工具如何辅助你做内核开发？
10. 你们为内核/容器开发沉淀了多少个 skill？各自负责什么？
11. 你用的 agent host / 平台是什么？skills 和 agent 是如何编排、按流程跑起来的？
12. 有遇到过 AI “翻车”的情况吗？是怎样的场景？你如何处理和规避？
13. 现在用 AI 生成的代码，大致可用性有多少（比如通过率或正确率）？
14. 你觉得最近可用性提升 20–25% 的原因是什么？你做了哪些优化（比如 skill、prompt、worktree 等）？
15. 你认为还有哪些方式可以进一步提升 AI 辅助开发的效果（接近 90% 可用）？
16. 你了解过不同大模型在编码/推理方面的差异吗？哪些模型更适合编码？日常怎么选用？

四、系统设计 / Web 场景理解

17. 如果要给 cgroup 的资源调用量做一个 Web 管理界面，前后端的交互会怎么设计？如何保证实时查看、更新的及时性和稳定性？
18. 你在 serverless 容器平台里做的 Web / API 交互是怎样的？前后端联调是如何通过路由和 HTTP 请求实现的？

五、Agent 与社区产品思考

19. 你们社区有哪些面向用户的产品（如 BBS 论坛）？
20. 如果要让 AI 更好地服务社区用户，你会设计怎样的产品或 agent？
21. 除了问答场景，你们目前是否在 GitHub / 代码审查中使用 AI 进行 PR 审查、辅助代码 review？

六、算法 / 编碼题

22. 实现一个字符串解码算法：给定带数字和中括号的编码字符串（可能嵌套），解码为原始字符串，要求给出思路并实现。
23. 对刚才解码题的实现，你觉得还有哪些需要优化或可能没考虑到的场景？

七、职业规划与岗位匹配

24. 你现在写了很多内核代码，对个人未来的规划是什么？
25. 投递“小红书社区工程”这样的岗位，对你来说是怎样的方向（系统应用 / 全栈 / 后台）？
26. 如果岗位要求主要是 Java + Vue/TS 全栈开发，并且紧贴用户侧产品和体验，这和你对未来方向的预期是否匹配？

## 反问环节

1. 您是哪个业务线的？
   - 面试官：我们是社区这边的团队，本职主要做社区外部系统建设，包括小红书 PC Web、M 站、创作者服务平台，以及内部运营管理系统、工程控制系统、算法应用的 agent 平台等。

2. 实习生如果进来，主要会负责做什么？
   - 面试官：主要是做一些中后台系统的 agent 化改造、偏工程应用的全栈开发，后端以 Java 为主，前端是 Vue/TS，围绕社区用户和运营场景。

3. 面试评价如何？有哪些需要改进的地方？
   - 面试官：现场不做正式反馈。从专业相关（内核、Rust、AI 开发）来看深度挺好，但在工程产品应用侧（面向用户的社区产品、Web 系统）经验偏少，小红书整体更偏重用户产品和工程应用开发。
