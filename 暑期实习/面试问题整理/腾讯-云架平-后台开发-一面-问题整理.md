腾讯-云架平-后台开发-一面-问题整理


面试问题

一、项目相关

1. 你先简单介绍一下自己。
2. 你这两个项目里，serverless 的那个项目时间比较短，做了四五个月就结束了，是吗？
3. 这两个项目本质上都是社区项目，对吗？
4. 这些项目做完之后，现在有人在用吗？有没有收到过实际反馈、功能升级诉求或者使用反馈？
5. Joviy OS 是华南理工自己维护的吗？
6. 你觉得这个系统如果和 Linux 比，最核心还缺什么？如果真要落地，最大的短板在哪？
7. 你们现在调度的问题具体是什么？
8. 如果要解决这个调度问题，你有思路吗？
9. Linux 在这些问题上是怎么做的？为什么它能做得更稳定？
10. 你们有做过和 Linux 的对比测试吗？比如进程管理、调度开销到底差多少？
11. 即使现在比 Linux 差，从机制或原理上，你觉得有没有可能做到比 Linux 更好？
12. Rust 虽然强调内存安全，但你们项目里是不是也会用 unsafe？用了 unsafe 以后，和 C/C++ 的差别还剩多少？
13. 你写的 Cgroup 机制，在 Linux 里到底是怎么生效的？
14. Cgroup 对进程数的限制你已经讲了，那运行过程里的 request 和 limit 你是怎么控制的？
15. Cgroup 既然跟调度相关，对性能要求会很高。你们这里用了什么高性能机制？
16. Linux 里的 Cgroup 发展到现在有几个版本？每个版本差异是什么？
17. 现在的 Cgroup 还有什么限制不了、或者满足不了某些场景需求的地方吗？
18. 能不能举一个实际场景，说明 Cgroup 目前解决不了什么问题？
19. 现在的 Cgroup 能描述网络隔离吗？比如一个容器限制 5G 带宽、另一个限制 2G 带宽，这种能表达吗？
20. 如果标准实现可以，你知道它大概是怎么做的吗？
21. 如果要描述一个网络限额规则，它的描述单元、配置对象应该是什么？

二、算法题

1. 做一道题：统计从 1 到 n 中数字 1 出现的次数。
2. 你可以先写一个暴力解，再想怎么优化。
3. 暴力结果对了之后，如果继续优化，你有什么思路？
4. 如果按数位拆分、按每一位出现 1 的组合来思考，你能不能推一下？
5. 如果写成算法，大概应该是什么样的思路？

## 反问环节

1. 想问一下您那边主要是做什么业务、什么开发方向？
   - 组里主要有三块：AI 基础设施和推理引擎、函数即服务相关的函数引擎与调度分发、边缘缓存引擎。

2. 能问一下这次面试里我个人表现上有哪些建议吗？
   - 第一，做 Cgroup 这类东西不能只停留在“实现了”，还要思考它为什么这样设计、工业界还有没有新需求、它的限制精度和 overhead 如何评价。
   - 第二，你做的东西其实比较扎实，但表达和讲述还可以更清晰，要把做过的内容梳理成更容易让别人听懂的方式。
