蚂蚁集团-27届暑期-AIInfra-一面-问题整理


面试问题

一、项目与背景

1. 你能先简单自我介绍一下吗？

二、AI Coding 实践

2. 你现在用 AI 做 coding 的水平大概是什么样？在你认识的人或社区里处于什么阶段？
3. 你在笔试里一上来先让模型实现一个 skill，这个 skill 的思路是什么？你希望它达成什么效果？
4. 到最后验收时你发现东西跑不起来，而且你自己也不太清楚应该怎么跑、怎么测，你觉得是哪个环节出了问题？
5. 这个问题主要是环境问题，还是其他问题？
6. 既然 README 里没写清楚最终形态，你有没有主动告诉 AI 最终应该做成什么形式？
7. 如果 AI 连怎么测试、怎么使用都不清楚，那你设计的这六个阶段怎么真正跑起来？尤其 feedback 这条链路怎么打通？
8. 整个过程中 AI 有没有做出你觉得不对的事情？你是怎么处理的？
9. 你一开始先问了模型是什么。你之前在笔试之外用过 MiniMax、Kimi 这类模型吗？
10. 你平常自己一般都用什么模型？你觉得它们分别适合做什么事情？
11. 你中间花了不少轮去调 skill，还尝试让它下载 skill creator 一类的能力去优化。你觉得问题主要出在 skill 描述本身吗？
12. 后来优化完之后，你觉得效果有变好吗？
13. 你有 review 过 AI 自己写的测试吗？如果 AI 在同一个上下文里既写代码又写测试，这样的约束真的足够吗？
14. 你现在在项目里让 AI 参与 coding 的比例大概有多少？从代码量和时间上分别怎么看？
15. 你会详细 review AI 最终产出的代码吗？
16. 你大概是从什么时间点开始正式转向使用 AI Coding 这一套工作流的？

三、Skill 与 MCP 理解

17. 你能谈一下你对 MCP 和 skill 这两个东西的认识和理解吗？
18. 这两者有什么区别？各自的优势和劣势分别是什么？

四、AI 趋势与岗位匹配

19. 这几个月面对这次 AI 革命，你自己的感受是什么？
20. 你怎么看“程序员会被 AI 取代”这样的趋势？
21. 如果来我们这边做基础设施，你比较感兴趣哪个方向？比如云底座、K8S 平台、基础网络、基础内核等。

---

## 反问环节

1. 蚂蚁集团内部对 AI 的态度是什么样的？日常使用外部 SOTA 模型会不会有限额？
   - 面试官表示，公司内部已有统一推理平台，内部开源模型和自研模型的 token 基本不设硬限制；外部模型也可使用，当时像业界 SOTA 模型大致是每人每天约 2000 万 token，超额后还可以再申请。

2. 你们部门的业务线主要做什么？
   - 部门是超级计算部，负责蚂蚁整体计算底座，覆盖 IaaS 计算节点供应、K8S 容器平台、中间件以及内核/操作系统等基础设施能力，为上层各业务提供统一底座。

3. 这次面试你对我的评价是什么？我有哪些地方可以改进？
   - 面试官整体观感较好，并明确表示“我这边是 ok 的”；建议重点提升两点：一是先把最终产出定义清楚，先拆清需求和交付标准；二是抓住“头尾”，减少对 AI 中间过程的过度关注，让反馈标准更量化、更可验收。

4. 为什么约面时间里会有周六、周日？
   - 面试官表示，这是自己在系统里开放的可用时间，并非特殊安排；因为工作日白天较忙，所以也会把周末时间开放给候选人选择。
