### 3. 什么是死锁，怎么避免

**我的回答**：死锁就是两个对象需要对同一个资源进行操作。比如事务A和事务B同时需要对C和D做操作，一个先C再D，一个先D再C，两个事务都是抢占式调度，A拿C时需要D，B拿D时需要C，就会产生死锁。避免方式：尽量串行化，不能长时间持有锁...

**不足**：避免方法回答较泛，没有给出具体的技术方案

**回答关键词**：环路等待、资源竞争、加锁顺序、串行化

**参考回答**：
死锁四个必要条件：互斥、占有并等待、非抢占、环路等待。
避免方式：破坏任一条件，最常用的是统一加锁顺序（按ID排序）、设置超时时间、死锁检测算法。

### 4. 转账死锁问题（重点短板）

**我的回答**：通过时间戳，按先发起交易的人先保护...（被否）把加钱和扣钱分成两个操作...（被否）

**不足**：思路完全偏离，时间戳方案有bug，拆分操作违反原子性

**回答关键词**：按ID排序加锁、统一加锁顺序、避免环路等待

**参考回答**：
按账户ID排序加锁。无论谁给谁转账，都先锁ID小的账户，再锁ID大的账户。这样所有转账操作的加锁顺序一致，不会形成环路等待。
扩展：分布式场景可用分布式锁 + ID排序，或全局事务ID排序。

### 5. Linux常见进程状态

**我的回答**：就绪、阻塞和等待。就绪是准备执行，分配CPU时间片后开始运行；碰到IO读取时CPU软中断变成阻塞状态；阻塞完成后数据准备好，回到就绪状态。

**不足**：状态名称不够准确（应该是运行、就绪、阻塞），缺少僵尸态、停止态等

**回答关键词**：TASK_RUNNING、TASK_INTERRUPTIBLE、TASK_UNINTERRUPTIBLE、TASK_ZOMBIE、TASK_STOPPED

**参考回答**：
- TASK_RUNNING：运行或就绪
- TASK_INTERRUPTIBLE：可中断睡眠（等待IO）
- TASK_UNINTERRUPTIBLE：不可中断睡眠（内核态等待）
- TASK_ZOMBIE：僵尸进程（已终止但未被父进程回收）
- TASK_STOPPED：暂停（收到SIGSTOP信号）

### 10. 三数之和

**我的回答**：先排序，遍历k从0到n-1，每次用双指针i在k+1、j在末尾...（实现时调试较久）

**不足**：调试时间过长，重复元素跳过逻辑写错位置

**回答关键词**：排序、双指针、去重、O(n²)

**参考回答**：
```python
def threeSum(nums):
    nums.sort()
    res = []
    for k in range(len(nums)-2):
        if k > 0 and nums[k] == nums[k-1]: continue  # 去重
        i, j = k+1, len(nums)-1
        while i < j:
            s = nums[k] + nums[i] + nums[j]
            if s < 0: i += 1
            elif s > 0: j -= 1
            else:
                res.append([nums[k], nums[i], nums[j]])
                while i < j and nums[i] == nums[i+1]: i += 1  # 去重
                while i < j and nums[j] == nums[j-1]: j -= 1  # 去重
                i, j = i+1, j-1
    return res
```
