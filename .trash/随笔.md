- 讲一下shared_ptr、unique_ptr、weak_ptr的原理，shared_ptr底层是如何实现的
1. unique_ptr：极致的独占所有权

unique_ptr 是最轻量级的智能指针，它的核心原理是禁用拷贝，只允许移动。

    实现原理： 在类定义中，unique_ptr 删除了拷贝构造函数和拷贝赋值运算符（使用 = delete），但实现了移动构造和移动赋值。

    零开销（Zero-overhead）： 它的内存布局中只包含一个原始指针。当 unique_ptr 离开作用域时，析构函数会自动调用 delete。

    应用场景： 确定对象只有一个所有者时使用，性能等同于原始指针。

2. shared_ptr：共享所有权与引用计数

shared_ptr 允许多个指针指向同一个对象，其核心是引用计数（Reference Counting）。
底层实现架构

shared_ptr 的物理结构比 unique_ptr 复杂得多。一个 shared_ptr 对象在栈上占 16 字节（64 位系统），包含两个指针：

    指向实际对象的指针（Stored Pointer）。

    指向控制块的指针（Control Block Pointer）。

控制块（Control Block）内部结构

控制块是在堆上独立分配的一块内存，包含：

    Shared Count（强引用计数）：记录有多少个 shared_ptr 指向该对象。

    Weak Count（弱引用计数）：记录有多少个 weak_ptr 指向该控制块。

    自定义删除器（Deleter）：如果用户提供了自定义的释放逻辑。

    Allocator：用于分配控制块的分配器。

关键操作流程

    拷贝构造：增加控制块中的 Shared Count（原子操作）。

    析构函数：减少 Shared Count（原子操作）。

        如果 Shared Count 变为 0：调用对象的析构函数，释放对象内存。

        如果此时 Weak Count 也为 0：释放控制块自身的内存。

    线程安全性：引用计数的增减是原子操作（通常使用 std::atomic），因此在多线程下增加/减少引用计数是安全的，但并发读写同一个指针对象本身并不是线程安全的。

3. weak_ptr：不控制生命周期的观察者

weak_ptr 是为了配合 shared_ptr 而生的，它观察对象，但不拥有对象。

    原理：它指向 shared_ptr 的控制块，但它只增加控制块中的 Weak Count，而不增加 Shared Count。

    解决环形引用：
    如果 A 持有 B 的 shared_ptr，B 持有 A 的 shared_ptr，它们的 Shared Count 永远不会降为 0。将其中一方改为 weak_ptr 即可打破僵局。

    使用方式：weak_ptr 不能直接解引用。必须调用 lock() 方法。

        如果对象还活着，lock() 返回一个新的 shared_ptr（此时强引用计数 +1）。

        如果对象已销毁，返回一个空的 shared_ptr。

4. 性能考点：make_shared 为什么更好？

在面试中，面试官常问：shared_ptr<T> p(new T) 和 make_shared<T> 有什么区别？

    两次分配 vs 一次分配：

        new T 模式：先在堆上分配 T 的内存，再在堆上分配控制块的内存（两次 malloc）。

        make_shared：直接在堆上开辟一块连续内存，同时存放 T 和控制块（一次 malloc）。

    内存局部性：一次分配内存更紧凑，对 CPU 缓存更友好。

    潜在缺陷：如果使用 make_shared，只要还有 weak_ptr 指向控制块，整个连续大内存块就不会被释放（即使 T 已经析构了），因为控制块和 T 在同一块内存里。
