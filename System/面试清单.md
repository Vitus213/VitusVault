cgroup 源码背诵
- kernel/src/cgroup/core.rs 定义了 DragonOS cgroup MVP 的全部内核态状态机：CgroupNode 表示层级节点，持有 children、tasks、subtree_control、pids_max、pids_events_max 等字段，提供增删任务/子节点、查询祖先、子树任务计数等 API；CgroupRoot 管理全局根、ID 分配以及路径解析/创建/删除，是系统里唯一能生成和释放节点的入口；TaskCgroupRef 则是 PCB 上引用 cgroup 的轻量封装。  
- 功能方面核心模块支持三类控制：1) 路径与拓扑：cgroup_path_relative_to_node/cgroup_path_from_view/cgroup_common_ancestor 等为 procfs、cgroupfs、namespace 计算不同视角下的路径；2) 任务迁移/计帐：cgroup_accounting_lock、cgroup_migrate_vet_dst、cgroup_migrate_vet_dst_with_src、cgroup_can_fork_in 等负责 no-internal-process、pids.max 检查以及 fork/attach 前的容量校验，并通过 pids_events_max 计数违规事件；3) 节点 CRUD：create_child、remove_child、find_path、find_or_create_path 让 cgroupfs 在 mkdir/rmdir 时同步更新内核结构。  
- 连接关系：  
  - kernel/src/filesystem/cgroup2/mod.rs 直接依赖该文件提供的所有操作：挂载时调用 cgroup_root().root()，目录项动态遍历/创建依赖 children()/create_child，写 cgroup.procs 需要 cgroup_migrate_vet_dst_with_src、cgroup_accounting_lock，cgroup.subtree_control 操作依赖 subtree_control() 等 getter/setter。  
  - /proc/[pid]/cgroup (kernel/src/filesystem/procfs/pid/cgroup.rs) 通过 cgroup_path_from_view 与 ProcessManager::task_cgroup_node() 配合，为用户空间提供当前 namespace 视角下的路径。  
  - kernel/src/process/namespace/cgroup_namespace.rs 用 cgroup_root_node() 初始化根 namespace，并在 copy_cgroup_ns 中记录当前任务的 task_cgroup_node() 作为新 namespace 的 root_cgroup；同时通过这些辅助函数完成 namespace 间路径投影。  
  - 进程管理入口（ProcessManager/PCB）为每个任务维护 TaskCgroupRef，通过 TaskCgroupRef::node() 与 core.rs API 对接，在 fork、exit、迁移时更新 tasks 集合。  
  - 未来 controller 扩展、调度/资源统计都会以 core.rs 为唯一共享数据结构，其他文件仅暴露视图或 sysfs/procfs 接口。
